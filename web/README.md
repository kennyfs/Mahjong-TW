# 台灣麻將 on the web

The app's screens in a browser (practice, battles online, analysis, records, rules and settings, the rules explained
and the tour), in Traditional
Chinese (Taiwan), with the repository's engine compiled to WebAssembly and run in a worker. Svelte 5 and Vite; a static
site (relative paths, the screen in the address's fragment: `#/play`, `#/records/review`), so any file server and
folder will do. Battles need a battle server at the same address (`/ws`; docs/battle.md). Status and decisions:
[docs/app.md](../docs/app.md).

Layouts: a phone sideways (the main one: the table fills the window, full screen at the first tap), a phone upright
(the hand wraps after 8 tiles), and a computer (a rail at the side, a side panel with the scores and keys, one click
to discard, keyboard play: ← → to choose, Enter to discard, H G P C and Space for claims).

## Code

| Path | What |
|---|---|
| `engine/` | `engine.cpp`: `GuiEngine` (cpp/command/guiengine.h) behind two C calls for Emscripten; its CMakeLists (the same sources as the app's JNI library). |
| `build-engine.sh` | Builds it into `engine-files/engine.js` and `engine.wasm` (not in the repository). |
| `scripts/strings.mjs` | The app's `strings.xml` into `src/generated/strings.json` (run by `dev` and `build`): the page has no strings of its own. |
| `src/lib/engine.ts`, `engine-worker.ts`, `stored.ts` | The engine's requests (docs/gui-engine.md) to the worker; the WebAssembly kept in the Cache Storage. |
| `src/lib/layout.ts` | The table's sizes from the room it has (the app's `TableLayout.kt` is a port: change both). |
| `src/lib/practice.svelte.ts`, `battle.svelte.ts`, `records.svelte.ts`, `settings.svelte.ts`, `rules.ts`, `position-editor.svelte.ts`, `nav.svelte.ts` | The state: practice (the page is the authority), the battle client (a port of the app's `Battle.kt`), the records (localStorage), the settings, the rules, the analysis' position, the screen in the address. |
| `src/lib/tile-art.ts` | The tiles' paths, generated by `art/make_tiles.py` (as the app's `TileArt.kt`). |
| `src/components/` | The screens (`Play`, `Battle`, `Analyze`, `Records`, `Replay`, `DecisionAnalysis`, `Rules`, `Settings`, `Guide`: the rules explained) and their parts (`Table`, `MyHand`, `River`, `Melds`, `SeatBadge`, `ClaimBar`, `HandResult`, `AnalysisList`, `Tile`, `Tour`, ...). |
| `src/lib/tour.svelte.ts` | The tour's steps (each lights an element marked `data-tour`) and the first start's welcome card (the app's `ui/Tour.kt`). |
| `tests/engine-native.mjs` | The WebAssembly engine against the native one: the same requests, the same answers. |
| `scripts/shots*.py` | Screenshots and the end-to-end battle test, in headless Firefox (Playwright). |

## Building

Node 24 and npm; the emsdk (6.0.13, with its cmake and ninja) for the engine. On this machine:

```bash
cd web
npm ci
# The engine as WebAssembly (once, and after every change in cpp/): engine-files/.
source $THIRTEEN_WORK/emsdk/emsdk_env.sh
# It links a reduced ONNX Runtime for WebAssembly (ORT_WASM_DIR; Thirteen's build covers this network's operators)
# and copies the network the page ships (MODEL) to engine-files/actor.onnx: the app's, with float16 weights (2.2 MB;
# android/README.md makes it with python/fp16_weights.py), exported with the outputs the AI coach reads
# (python/export_actor.py; an older file works, the coach's digest without them).
TMPDIR=$WORK/tmp JOBS=16 ORT_WASM_DIR=$THIRTEEN_WORK/ort-wasm \
  MODEL=$WORK/models/actor_50.fp16.onnx ./build-engine.sh 2>&1 | tee $WORK/logs/web-engine-build.log
# The same answers as the native engine (built with ONNX Runtime), the network's figures to 0.002.
node tests/engine-native.mjs engine-files/engine.js ../cpp/build/mahjong
# The dev server (http://127.0.0.1:5180/; /ws goes to BATTLE_SERVER, default ws://127.0.0.1:8091).
npm run dev -- --host 127.0.0.1 --port 5180 > $WORK/logs/vite-dev.log 2>&1 &
# The site: strings, type check (svelte-check), dist/.
npm run build 2>&1 | tee $WORK/logs/web-build.log
```

The network: the page fetches `actor.onnx` when a request first names it (a network bot, a review, the analysis
screen), writes it into the engine's file system (`MODEL` in `src/lib/engine.ts`) and keeps it in Cache Storage; a
review of a hand takes about 0.1 s after that. `scripts/shots-review.py` plays a hand and takes the review's (its
decisions, the list with its rows each way, the last move, the end and the result), the analysis screen's, the
settings' and the rules' screenshots. `server/Dockerfile` does not build the engine with the network
yet (its `web-engine` stage needs ONNX Runtime for WebAssembly and a model stage, as Thirteen's has).

`server/Dockerfile`'s `site` target builds the same in Docker (the engine with the `emscripten/emsdk:6.0.13` image)
and serves it with Caddy beside the battle server (docs/battle.md).

## Screenshots and tests

The page opened with `?test` exposes its state as `window.mahjong` (practice, engine, settings, nav, shared, editor,
records, battle) for the scripts. They use the Playwright venv at `$THIRTEEN_WORK/pwenv` (Firefox):

```bash
PY=$THIRTEEN_WORK/pwenv/bin/python
OUT=$WORK/shots/web
# The table at each size: phone-land, phone (the standard phone, 923 x 411 and 411 x 840 CSS px at 2.625), fhd
# (1920 x 1080), laptop (1366 x 768), and variants (phone-land-dark, small-land, tablet-land). A fixed seed.
$PY scripts/shots.py http://127.0.0.1:5180/ $OUT phone-land,phone,fhd,laptop
# The other screens: a hand's result, its review and a decision's analysis, the analysis screen, records, settings, rules.
$PY scripts/shots-screens.py http://127.0.0.1:5180/ $OUT phone-land,phone,fhd,laptop
# Battles end to end: two browsers, a table game and a contest, one reloading mid-hand, on a local battle server
# started with a short pace (docs/battle.md).
$PY scripts/shots-battle.py http://127.0.0.1:5180/ $OUT/battle
```

Look at the screenshots after every change that shows.
